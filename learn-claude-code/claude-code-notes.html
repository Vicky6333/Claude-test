Claude Code 完全拆解

从零理解 AI Agent 架构 · 适合文科背景、零代码基础的读者

模型是驾驶者，Harness 是载具

核心循环 · 所有章节的基础

用户提问
↓
AI 思考 → 决定调用工具
↓
执行工具，把结果返回给 AI
↓
AI 继续思考 → 还要调用工具？
↓ 不需要了
返回最终答案

这个 while 循环贯穿 s01 到 s12，每节只是在它上面加一层机制。

第一阶段

让 AI 转起来（s01 – s02）

s01
Agent Loop
"One loop & Bash is all you need"

解决什么问题：没有循环时，AI 每次回答完就停了，你得手动把结果粘回去继续问。你自己就是那个循环，很累。

没有 Agent：  你 → 问AI → 复制结果 → 执行 → 粘回来 → 继续问…（你在手动循环）
有了 Agent：  你 → 问AI → AI自己转 → 完成    （AI在自动循环）
AI 能自己转了
s02
Tool Use
"加一个工具，只加一个 handler"

解决什么问题：只有 bash 一个工具时，所有操作都走终端命令，既不安全也不灵活。

解决方案：用一张「调度表」管理所有工具。AI 说"我要用 read_file"，代码查表，找到对应函数执行。想加新工具，只需往表里加一行，循环本身永远不用动。

工具名干什么
bash执行终端命令
read_file读文件
write_file写文件
edit_file修改文件中的某段文字
AI 能用多种工具了
第二阶段

让 AI 不迷路（s03 – s06）

s03
TodoWrite
"没有计划的 agent 走哪算哪"

解决什么问题：多步任务时，AI 对话越来越长，早期指令被"挤出"注意力。做 10 步任务，做完前 3 步可能就忘了后面 7 步。

解决方案：让 AI 自己维护任务清单，同一时间只能有一个 [>]，强制专注当前这步。

[ ] 第1步：读文件          ← pending（待办）
[>] 第2步：加类型注释      ← in_progress（进行中）
[x] 第3步：写测试          ← completed（已完成）

催更机制：AI 超过 3 轮不更新清单，系统自动插入提醒。不靠自觉，靠代码强制催。

对应 Claude Code：你用 Claude Code 时看到的任务进度列表，就是这个原理。
AI 不会在长任务里迷路了
s04
Subagent
"大任务拆小，每个小任务干净的上下文"

解决什么问题：AI 干活越久，记忆里堆的垃圾越多（读了 20 个文件的内容全在记忆里），越来越容易被历史淹没。

解决方案：派一个「小弟 AI」去干脏活，只把结论汇报给「老板 AI」：

老板AI（记忆干净）                  小弟AI（用完即扔）
┌──────────────┐   派任务 ──────▶ ┌──────────────┐
│ 记忆: [...]  │                  │ 记忆: []全新 │
│              │                  │ 读了20个文件  │
│ 结果: "pytest"│◀── 只返回结论 ─ │ 执行了30条命令│
└──────────────┘                  └──── 记忆丢弃 ┘
AI 能分工了，不被历史淹没
s05
Skills
"用到什么知识，临时加载什么知识"

解决什么问题：把所有专业知识都塞进 AI 的"开场白"太浪费——10 份手册 × 每份 2000 字 = 20000 token，大部分跟当前任务无关。

解决方案：两层加载。

第一层（始终存在，便宜）：
  只放技能名称和一句描述，AI 知道有什么可用

第二层（按需加载，用到才取）：
  AI 说"我需要 git 规范" → 这时才把 2000 字完整内容加载进来
对应 Claude Code：项目里的 CLAUDE.md 文件就是第一层，告诉 AI 这个项目有什么规范。
AI 不被无用知识撑死了
s06
Context Compact
"上下文总会满，要有办法腾地方"

解决什么问题：AI 的记忆有容量上限，读 30 个文件、跑 20 条命令轻松撑满，撑满了就没法工作了。

解决方案：三层压缩，激进程度递增。

层级触发时机做什么
第一层：微压缩每轮自动把 3 轮前的工具结果替换成一行占位符
第二层：自动压缩记忆快满时把完整对话存硬盘，让 AI 总结成摘要替换历史
第三层：手动压缩AI 主动触发和第二层一样，AI 自己觉得该整理时用
对应 Claude Code：你偶尔看到"上下文已压缩，继续工作…"就是这个机制。
AI 可以无限工作，不会被记忆撑死
第三阶段

让目标跨越对话存活（s07 – s08）

s07
Task System
"大目标要拆成小任务，排好序，记在磁盘上"

解决什么问题：s03 的任务清单只在内存里，一旦压缩就消失，而且没有依赖关系。

解决方案：每个任务变成一个 JSON 文件存在硬盘，带依赖关系。

任务1（已完成）
    ├── 任务2（等任务1完成才能开始）──┐
    └── 任务3（等任务1完成才能开始）──┤
                                       └── 任务4（等2和3都完成）

自动解锁：完成任务1，系统自动把它从任务2和3的等待列表里删掉，不需要人工维护。

为什么重要：这是后面多 AI 协作的共享看板基础——就像团队共用一个 Jira。
目标跨对话、跨压缩永久保存，还带依赖顺序
s08
Background Tasks
"慢操作丢后台，agent 继续想下一步"

解决什么问题：npm install、跑测试、docker build 这些命令要好几分钟，AI 只能傻等。

解决方案：把慢命令丢到后台线程，AI 继续干其他事，完成了自动通知。

t=0s  → 后台启动: pytest（预计30秒）
t=0s  → AI 开始写文档（不等 pytest）
t=10s → 文档写完，AI 继续做别的
t=30s → pytest 完成，结果进通知队列，下轮自动告知 AI
慢任务不阻塞 AI，并行执行
第四阶段

多个 AI 组成团队（s09 – s12）

s09
Agent Teams
"任务太大一个人干不完，要能分给队友"

解决什么问题：s04 的子 AI 是一次性的，用完即销毁，没有身份，不能持续通信。

解决方案：给每个队员一个文件邮箱。发消息 = 往对方文件追加一行 JSON；收消息 = 读取自己的文件，读完清空。

.team/
  config.json      ← 团队花名册（谁在、什么角色、什么状态）
  inbox/
    alice.jsonl    ← alice 的收件箱
    bob.jsonl      ← bob 的收件箱
    lead.jsonl     ← 队长的收件箱

队员生命周期：上岗工作 → 任务完成变空闲 → 收到新任务继续工作（不会消失）。

多个 AI 能互相通信，持续协作
s10
Team Protocols
"队友之间要有统一的沟通规矩"

解决什么问题：s09 的队员没有正式协商机制——直接杀线程可能损坏文件，危险操作没有审批就执行。

解决方案：两套握手协议（关机握手 + 计划审批），共用同一个模式：唯一的 request_id 把请求和响应串起来。

队长 ──shutdown_request──▶ alice  {request_id: "abc"}
队长 ◀──shutdown_response─── alice  {request_id: "abc", approve: true}

bob ──plan_approval──▶ 队长  {request_id: "xyz", plan: "重构认证模块"}
bob ◀──plan_approval_response─── 队长  {approve: true}
协作有规矩，可追踪、可审批、可拒绝
s11
Autonomous Agents
"队友自己看看板，有活就认领"

解决什么问题：队员只在被指派时才动，任务看板上的任务要队长一个个手动分配，团队大了管不过来。

解决方案：队员有 WORK / IDLE 两个阶段，空闲时每 5 秒自动扫看板。

WORK 阶段（干活）
    ↓ 干完了，进入空闲
IDLE 阶段（每5秒扫一次，最多60秒）
    ├── 查收件箱 → 有消息? → 回去干活
    ├── 扫任务看板 → 有没人认领的任务? → 认领 → 干活
    └── 60秒没活 → 自动关机

防抢锁：多个队员同时看到同一个任务，互斥锁保证只有一人抢到。
身份重注入：上下文压缩后，系统自动告诉 AI "你是 alice，后端开发"。

队员自己找活，自己协调，自己关机
s12
Worktree Isolation
"各干各的目录，互不干扰"

解决什么问题：所有队员在同一个目录干活，两人同时改 config.py，互相覆盖，谁也没法干净回滚。

解决方案：给每个任务开一个独立的 git 目录（worktree），用任务 ID 绑定。

控制层（.tasks/）          执行层（.worktrees/）
  task_1.json  ←──→      auth-refactor/   alice 在这里改代码
  task_2.json  ←──→      ui-login/        bob 在这里改代码

alice 和 bob 改同一个文件，各改各的，完全不冲突。完成后一行命令：删目录 + 任务自动标完成 + 写事件日志。

并行不冲突，每个任务有自己的独立空间
